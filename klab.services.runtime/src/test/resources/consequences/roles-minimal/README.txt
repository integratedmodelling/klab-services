Self-contained minimal accepted-world fixture

This is a separate core-only authored worldview plus the same process/model/k.Actors protocol
as ../roles. It has no CHEM/UN authority dependencies and does not remove any requirement or
declaration from the original fixture or managed worldview. It may only be loaded in an isolated
acceptance environment coordinated by the parent task. Never install it over the user's imod.

The namespace and testcase remain consequence.roles.*; semantic literals use this fixture's
authored imod:Bearer/Birth/Marked/ImpliedValue. There is deliberately no role characterization
model. Acceptance must use the actual semantic factory, parser/adapters, namespace model admission,
ordinary Runtime pipeline, private normal query issuer and native commit guards.

The final exact query uses ImpliedValue optional: implication submits the authored unitless
target as an optional request. The resolving model's metre output does not change that requested
observable identity. Context queries retain exact observable matching; the preceding consequence
inspector separately checks semantic compatibility and actual committed bearer placement.

The repeated ordinary submission is also a causal-cycle barrier: Runtime admits a new explicit
root only after every lease of the preceding cycle drains. Its reference result must preserve
the implied target identity, and the role must remain attributed after optional characterization
has reached its terminal outcome. No fixed sleep or inferred quiet interval is used.

Successful execution of this fixture does not establish canonical full-managed-world acceptance.
Original full-world fixture acceptance and independent user validation must be reported separately.


The isolated worldview must also load strategies/observations.obs. It contains the canonical
rank-zero substantial.direct, dependent.direct and characterization.direct routes; an accepted ontology alone does not
supply ordinary observation strategies. Keep this file in the worldview project, not the model project.
The characterization route is necessary to query models and establish genuine NO_MODEL evidence;
the absence of any applicable strategy is not evidence of model absence.
