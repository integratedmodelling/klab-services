# Completed work in a fresh Python process

The `completed-recovery` owned TEST suite verifies existing public saved-handle
APIs, not a new restoration abstraction. It creates a separately labelled
synthetic 5×4 nonuniform Java field, saves focused context/Job/observation handles,
then launches a separate Python process using the installed noneditable SDK and
separately configured credentials. It compares the same original identities,
focus and all20 independently specified numeric/missing cells. Closing the child
must not dispose the server context: the creator reads it again before explicitly
releasing only its own work. Foreign-principal and deleted-context restoration
must fail rather than silently create work.

The recovery worker audits HTTP methods/paths through local close: only GET reads
and existing POST knowledge-query/value-read routes are allowed; no creation,
scientific resubmission or release is permitted. User-scope initialization is
explicit before that audit. Source-data zero, negatives, float64 precision and
missingness are independently checked; handles must contain neither test token.
The parent runner restricts private evidence permissions, hides owned windows and
verifies owned process/listener cleanup without touching unrelated Java services.

```powershell
<installed-python> python-client/tools/run_reliability_acceptance.py `
  --server-repo <explicit-compiled-server-checkout> --java <jdk21-java.exe> `
  --components <two-pinned-component-manifest.json> `
  --state-dir <fresh-private-external-directory> --scenario completed-recovery
```

Requires the existing accepted compiled Java tuple, explicit two-archive hashes,
and free reserved loopback ports. Failures are not retried as mutations; inspect
the private evidence and classify them. No shared Modeler/custodian data is used.

**Limits:** completed retained work in one live Runtime incarnation only. In-flight
Job retention, Job history expiry, Runtime restart/generation, durable execution
continuation, collaborator writes, production Hub onboarding and whole RC-P1.2/
P3.3 acceptance are not claimed. The original legacy-workflow failures remain
separate; test `consolidation` semantics do not migrate historical worldviews.
This synthetic scientific workflow is not replication of any published study.
