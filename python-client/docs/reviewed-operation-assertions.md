# Reviewed operation assertions

`operation-workflow-mappings.json` contains explicit human-reviewed assertion
descriptions and nonnative authority labels. A mapping counts only when its exact
repository test function passed and its executed file hash matches current bytes in
a fresh trace of the exact installed SDK. Changed tests or package bytes cannot
inherit stale measured associations.

The current local review links **219 operations**, with **287 still missing** across
506 classifications. All455 nonabstract operation bodies were observed;51 abstract
declarations remain uncalled. Neither presence nor a reviewed description proves
whole-function correctness or every positive/negative requirement. Abstract missing
evidence is not relabelled as an unsupported production operation.

Coverage includes selected local DTO/codecs, core sync/async workflows, semantic and
catalog inspection, import/source workflows, conditional reference publication,
sharing/notifications, managed-behavior lifecycle and recorded dependency/explanation
inspection. Authority labels distinguish local data, mocked HTTP, independent finite
reference services and orchestration doubles. Recorded authentic data is not a new
native scientific run; finite source publication is not native admission/release.

Tracing measures bounded owning-thread call/resume presence only. It records no
arguments, results, parameter values or their hashes. Other threads, subprocesses and
notebook kernels are unmeasured, even when their separate workflow tests pass. Tests
using real threads or doubled Job waits do not acquire native scheduler authority.

Original-row reconciliation, actual Java compatibility/science, issuer/rights,
deployment/scale, OS/container isolation and release approval retain separate gates.
