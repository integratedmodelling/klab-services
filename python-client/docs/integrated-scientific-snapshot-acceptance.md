# Installed scientific-snapshot reference acceptance

`tools/verify_scientific_matrix.py` integrates public sync/async multishard reads,
frozen recorded GeoTIFF exports, numerical analysis and offline known-answer controls.
It uses the same installed-byte, executable-test, support/helper and runner custody
engine as onboarding/restoration/notebooks. Three groups keep SDK contracts, isolated
offline/table HTTP probes and independent reference-service workflows separate.

```text
python tools/verify_scientific_matrix.py --artifact-receipt RECEIPT.json --output-directory NEW_DIRECTORY
```

The explicit prior artifact receipt binds installed module bytes. Frozen fixture
files (including binary TIFF/Avro and JSON oracles) are now also pinned before/after;
installed reference fixtures must match checkout oracle bytes. This closes a gap where
unchanged Python modules alone would not detect a changed non-Python test oracle.
Repository `.gitattributes` remains pinned as support metadata but is not required
inside the package fixture directory; it is not a runtime oracle or packaged asset.
Failure, skip, empty group, overwritten output, changed module/test/helper/oracle and
timeout evidence cannot produce a success receipt. Failed diagnostics are retained.
`--capture-current-source` remains installed-module/source parity, not wheel/sdist or
fresh dependency isolation; a matching hash is custody, not scientific authority.

Known-answer controls independently check finite values, zero/negative/missing/NaN
distinctions, masks, explicit offsets/order, float64 precision beyond float32, CRS,
affine coordinates and explicit window/state identities. Read-plan hashes are local
reference identities, not native commits. Full original authentic TIFF bytes are
preserved without guessing absent embedded georeferencing. Interrupted/denied/oversize
exports must not publish partial results or overwrite existing user files. Offline
inspection follows explicit owner release and uses socket-forbidden fresh processes.
The isolated offline example pins both parent and nested `-I` subprocesses to the
actual selected installed SDK path. `-I` ignoring `PYTHONPATH` must not silently turn
pip-target verification into measurement of a different global installation. Example
source bytes are also part of the runner support snapshot.

**Recorded authentic data is not a new real-provider execution.** Synthetic arithmetic
is not provider accuracy or historical-study replication. Real Java scanner/provider
science still requires an approved pinned model/data/datum/tolerance oracle and actual
execution evidence. Dictionary/worldview/time claims, native lineage/retention and
production permission/deployment/release approval remain separate. No fallback or
Java/IDE/worldview/OS repair is authorized by reference acceptance.
