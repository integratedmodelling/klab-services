# Automatic independent predicate products and native family recovery

This isolated increment extends the preserved [family milestone](CLASSIFIER_DEPENDENCY_FAMILIES.md).
It supports multiple direct positive abstract ATTRIBUTE occurrences on one quality dependency of
one selected INIT model, in the same explicit named native domain. One graph-reading contextualizer
executes after the independent concrete dependencies. It supplies its own authored calculation.
Other deferred dependencies, mixed/inherent multi-occurrence domains and shared-binding syntax
remain explicitly unsupported. Existing single-occurrence routes retain their earlier contract.

## Independent occurrences and one live discovery domain

The [prepared expansion contract](PREDICATE_DEPENDENCY_EXPANSION.md#product-and-eligibility-contract)
requires independent positional choices. A shared producer or completion does not correlate two
positions. Each Prepared RequestIdentity/path retains its own classifier family, closure and outcome;
all factors must affirm success before product application. Generated optionality cannot excuse a
missing, unresolved, failed or cancelled original classifier prerequisite. Typed redeclaration and
native-bearer/satisfiability/identity eligibility still precede concrete dependency planning.

Automatic continuation freezes every producer identity key before executing any producer. It
shares only an equivalent producer plan within this dependency's context, support, revision and
live parent attempt. Lowering records an ordered list of exact producing model URNs in actuator
data, including models contributing no computation; order and duplicate contributions are retained.
An unnamed contribution retains an empty marker, so mixing named and ad-hoc models cannot
masquerade as complete provenance. Missing, malformed or incomplete provenance disables
provisional root-ID coalescing without rejecting ordinary ad-hoc execution. Identical calls in one
namespace do not prove identical selected models. This tag is not a source-version reuse lease. All authored service arguments, model namespace constraints, metadata,
geometry, bindings and durable references remain significant. Plan-instance transient IDs are
not scientific inputs. Semantic type sets are canonicalized only at known typed observable
positions; metadata, annotations, values and service-parameter arrays retain authored order. Matching provisional root output IDs can be normalized for comparison only
for an unowned leaf OBSERVE/INIT/INSTANTIATION collective query: no durable URN, native/provisional
parent, participants, target bindings or child work. A provisional output already present in the
live transaction is rejected independently of that structural proof, including outputs whose
parent fields were changed when linked. Actual executable plans and actual output identities are unchanged.
Nested provisional IDs are retained conservatively. Automatic multiple-factor admission requires
one identical, eligible leaf producer before any discovery executes; distinct or uncertified plans
fail explicitly. This is no persistent discovery reuse lease.

The existing continuation then captures every occurrence against the same successful producer and
cohort-plus-attempt view before classifier effects. Sequential distinct-family effects use the
validated staged overlay. Every factor has complete fresh/reused outcomes and mandatory
characterization lookup before its classification child commits. Root commit still validates
source, native member/result snapshots and the live attempt on its native transaction. No semantic
revision is used as a membership certificate; no new invalidation or UNKNOWN retry policy is added.

## Characterization is still mandatory

In the crop fixture, characterization lookup completes with an explicit, nonempty NO_MODEL
Dataflow. This means no explanatory model is available after successful attribution. Runtime
calls and waits for CharacterizationLifecycle; it does not skip that lifecycle. Empty/error/failed
plans are failures. The regression forcing characterization failure proves that attributions and
parent output cannot publish. Missing required classifiers remain failures even when the known
member domain is empty. A later classifier failure rolls back earlier staged family effects.

## What native recovery actually verifies

Ordinary Runtime.submit still uses fixture catalogue/source-parser transport, component lookup and
native database adapters, while OWL/HermiT, strategy parsing, Resolver, scheduler, classification,
typed expansion, concrete computation, transaction staging and numerical storage run normally.
Completed output/children and exact family/mediation bindings are then fed into production
KnowledgeGraphNeo4j transaction store/link/commit against real embedded Neo4j. A fresh graph
instance with empty caches restores observation properties, geometry and metadata and reads
persisted incoming AFFECTS bindings. Actual family access runs with no current transaction.

The bridge supplies ID allocation and converts embedded Neo4j values to driver values, avoiding
unrelated Bolt/Netty startup conflicts. Queries, writes, commit/rollback, property serialization,
metadata/geometry restoration, edge direction and family validation use production code. Native
IDs assigned at this boundary are recorded and checked on reload. Test parser transport retains
full optional typed observable syntax by redeclaring authored concrete ASTs; semantic results
and native eligibility are not mocked. The tests cover distinct and shared-source bindings,
optional absence, successful empty inventory, changed role/attempt evidence and rollback.

This verifies a real native family persistence/recovery boundary. It does not claim that the
original ordinary-submission root commit itself used embedded Neo4j, that numeric storage bytes
were restarted, or that producer completion can be replayed. Persistent membership invalidation,
external datastore certification, outer-context composition and dimensional/FX mediation remain
outside this increment. See external verification/review receipts for the actual Maven result.

The subsequent [native-root verification](CLASSIFIER_NATIVE_ROOT_RECOVERY.md) installs the real
embedded graph and numeric storage before ordinary submission, then cold-reloads its own committed
results. It separately documents the counter/shard persistence repairs, exact test boundaries and
remaining infrastructure limits; the historical milestone above remains independently preserved.
