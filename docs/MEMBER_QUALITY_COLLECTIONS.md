# Native member-quality collections — isolated candidate

This document describes an isolated implementation candidate. It has not been merged,
published or accepted through a live stack. The current test receipt must accompany it.

## Three distinct bindings

A request has an existing invocation container (for example a Region), a discovered set
of actual members (Streams), and a native quality result for each member. The container
witness binds its observation identity, support, semantic service and knowledge revision.
Every quality result remains parented by its actual Stream and retains that Stream's
support. The collection is a typed view keyed by actual member identity; it is neither
a new group nor a Region-born quality, fake Observation, or scalar value.

Completed discovery over the exact container support is required. Existing native
observations and ordinary models can be reused through ordinary member submissions.
Successful completed discovery with no members returns an empty collection. Failed or
incomplete discovery does not mean an empty collection; no-data does not become zero or
absence. Cancellation stops further scheduling cooperatively and cancels the active
child future; it does not roll back already committed children.

## Existing grammar and distinct result kinds

The separate Runtime API accepts a typed member-quality request. A restricted existing
strategy MemberPlan can also be lowered through `resolveMemberPlan`: one collective
resolve, one member loop resolving a native quality within that member, and one yield.
This is an explicit typed API subset, not generic MemberPlan support in the existing
single-Observation strategy execution route.

A regional model may author a dependency such as `StreambedGradient of Stream` with a
named port and select a contextualizer using existing `using function(...)` syntax.
Its selected installed Java method must have an exact
`@KlabFunction.Input(name="port") MemberQualityCollection` parameter. Capability checks
inspect the installed method and reject ambiguous descriptors/overloads. Runtime
rechecks that actual method before invocation; parameter spelling alone, artifact
metadata, an untyped parameter or singleton guessing is insufficient.

Ordinary compatible Tier-0 Observation queries retain their existing precedence.
An ordinary Observation, Region field or single native quality is not a complete-member
collection. This slice has no direct-view model-output ABI, so a typed collection port
uses complete discovery followed by ordinary native per-member resolution/reuse.
It does not silently coerce an ordinary Tier-0 scalar into a collection.

## Source obligations and execution guards

Only the actual saved source occurrence with an explicit native-bearer clause can create
a pending typed dependency descriptor. Resolved native inherency alone does not prove
that authoring intent. The descriptor retains model, dependency index, exact original
observable spelling, named port, native bearer and canonical quality. It is unbound:
source preparation is not executable eligibility or an assertion that members exist.

The existing admission receipt binds source version/hash, stable executable digest,
reasoner identity/revision and pending descriptors. Catalogue discovery, model ranking
and runtime must all retain this obligation. An actuator binds it to its actual container
through a separate typed input map; ordinary Observation dependency maps remain intact.
The map must cover the receipt exactly. Runtime checks current saved source, actual
container/observer/revision, installed consumer, visible member identities and supports
before preparation and again before result consumption. Parent output storage and mapper
invocation follow successful input preparation.

Each typed alias must identify exactly one saved dependency, including ordinary inputs:
a typed and ordinary dependency cannot share an alias. An actual installed typed input
without the exact source descriptor is rejected. Runtime enumerates the selected
installed method's collection parameters even when the pending list and actuator map
are empty, rejecting missing or ambiguous bindings before allocation or discovery.

An installed-only inspection endpoint reports the complete typed parameter set, including
ports absent from source. Catalogue/model admission compares that set with the exact
pending source descriptors before distance/ranking. An authenticated UserScope suffices
for this pure method inspection; it does not bind an invocation container. Known empty
and unavailable inspection are distinct, and HTTP/decoding failures remain unavailable.
The inspection itself does not load or invoke components. The Resolver explicitly requests preparable catalog candidates and runs the existing
on-demand component/resource prerequisite path before this installed proof and ranking,
as described below. Default direct catalog queries retain executable matching.

Member support must match the actual native support within the container. A bounded
normalization recognizes only a singleton nonregular physical time interval whose
self-intersection adds its previously unspecified full-interval resolution. Dimension
rank/shape/generic/regular flags, temporal kind and any explicit resolution must survive.
Coverage or other extra temporal metadata cannot enter this fallback; richer supports
must be exactly equal or await an explicit mapping contract. Metadata is not discarded.

The source-admission subset requires a known unitless Ratio: OWL Ratio subsumption plus
explicit canonical `odo:unit="1"`, with no declared unit/currency and quantification
contextualization. Neither missing metadata, Ratio ancestry alone, nor dimensional
compatibility with unity is unitlessness proof. Explicit `observed as` dependencies are
currently outside this subset. Implicit requests may retain a compatible specific
result for the selected observer or an absolute fallback under the existing observer
contract; only observer refinement may differ, and the actual returned perspective is
preserved. Selected Agent observation identity is provenance, distinct from its class.

## Deliberately unfinished

Generic Height/MEASURE collection mediation, direct-view Tier-0 outputs, arbitrary
MemberPlan bodies, temporal process updates and general regional redistribution remain
outside this slice. Regional Elevation/Slope sampling for the original gradient model
has no implicit bridge: it must resolve through an explicitly supported operation or
fail before allocation. The original `degree_angle` declaration and formula are not
validated by adding canonical unity metadata.

A Region-wide result needs an explicitly selected contextualizer. A test-only maximum
over two native scalar values demonstrates that boundary; it is not a default ecological
mapping, sampling, overlap, gap, rasterization or aggregation policy.

## Compatibility and later rollout

The new Runtime operations, client methods, validation response fields and typed
Actuator input map require matching Services API/client artifacts. The separately
published unit-only `f88e9570` change does not contain these ABI changes. A future
deployment must coordinate those artifacts and clients; this candidate does not
authorize publication, deployment, IDE updates or a service restart. Isolated mapper,
controller and execution tests are not live/deployed acceptance.


## Prerequisite preparation and discovery modes

Catalog queries default to `EXECUTABLE`, retaining installed-consumer validation and semantic matching. Resolver requests `PREPARABLE` explicitly: these results retain source, native-bearer, exact pending occurrence and catalog visibility/type/coverage checks, but are candidate listings rather than executable grants or ranked matches. The Resolver captures an immutable source/executable/reasoner preparation snapshot, invokes the existing authorized Runtime contextualizer/resource prerequisite path under the candidate's namespace/project constraints, then rechecks that original snapshot and proves installed typed-port completeness before semantic distance and ranking. Inspection itself never loads or invokes a component. Missing/disabled/failed preparation, unavailable inspection, stale source, changed executable or changed semantic generation fails closed.

Prepared ResourceSets are cached only within the resolution compiler and exact invocation scope/context/observer/constraint witness; chosen model resolution reuses them and attaches only the selected requirements to provenance. This ordering can prepare more coarse candidates and resource prerequisites than the former selected-model-only path. It continues to use existing component-load settings and authorization; no live installation is exercised by the isolated tests. Known ordinary overload sets retain the existing executor's selection behavior when every installed implementation is inspectable and has no collection parameter. Typed or mixed overload ambiguity remains ineligible.


Preparation cache keys use model and scope identity plus immutable context, observer and constraint witnesses. Successful same-key preparation is atomic per key; there is no service-global preparation lock. Changing a context or observer requires independent proof/preparation. The existing root-Subject/Agent path selects in the requesting context and then enters the explained subject for computation. That intentional transition retains the original selection snapshot, independently prepares scope-sensitive resource prerequisites in the actual computation scope, and requires full re-admission against the same source/executable/reasoner snapshot before using those requirements; it does not transfer the container's contextual proof.
