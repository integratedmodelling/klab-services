# Selected-model classifier dependency families

This isolated increment extends the verified INIT singleton route in
[CLASSIFIER_DEPENDENCY_SUBMISSION.md](CLASSIFIER_DEPENDENCY_SUBMISSION.md). It implements the
owner-approved consumption contract: one selected model executes once after its independent
concrete dependency observations complete. Its contextualizer retrieves their prerequisite
bindings from the knowledge graph and performs an explicitly authored calculation. Expansion
itself neither aggregates values nor supplies a scientific reducer.

## Conditional admission remains a type proof

A direct positive abstract ATTRIBUTE on a native quality can create a pending classifier
obligation. Source authoring recognizes that obligation, while strict executable admission still
rejects it. Resolution uses an explicit classifier-preparable request/receipt mode; both accepted
and legacy Reasoner validation paths echo and match that mode and return occurrence evidence.
The saved source and bound model remain tied to one accepted revision before prioritization.
Concrete parent outputs, rather than unexpanded abstract dependencies, enter semantic distance.

The proof removes only supported plain named ATTRIBUTE slots from detached syntax, then checks
all remaining native, identity, generic and satisfiability obligations. Original full-source
applicability and disjointness validation still runs. Outputs stay strict, including a secondary
output semantically identical to a pending dependency. Independently abstract heads, selectors,
qualified predicates, incompatible native bearers, transformations and other semantic positions
are not made executable by this mode. The current capability requires an explicit supported
named native bearer; implicit or ambiguous domain inference remains outside it.

The selected model must subsequently obtain a real ordinary classifier/member-producer plan.
A conditional admission receipt does not certify that a classifier exists or has succeeded.
Successful precomputed Tier-0 alternatives are exhausted before automatic classifier planning,
including nested ordinary dependencies and explicit operation paths. Partial precomputed parent
output is not silently composed with a deferred parent.

## Classifier domain and native child context are distinct

The existing inherent-bearer singleton path retains its exact sole-current-member guard. A
separate direct-quality mode consumes the coherent cohort-plus-attempt member view after actual
producer success. Existing request-local member/source/result/attempt guards remain on the same
root commit; semantic revision alone is not a member-set certificate. Every keyed classifier
outcome must complete before its concrete closure produces dependency syntax.

Generated quality dependencies stay in the original observed native context. Their classifier
members are not substituted as native bearers. `Crop` qualifying `HarvestCashValue` and `Crop of
each Region` require independent authored applicability to the quality and to the classifier
domain. This does not infer physical parthood, observational containment, spatial coverage or
scientific completeness from cohort membership or an extent intersection.

Only the supported request-local cohort input contract is used. Long-lived discovery/reuse,
shared binding syntax, UNKNOWN retry/lifetime, membership invalidation and outer-context sampling
or typed composition are not implemented here.

## Execution, graph inventory and optionality

Each concrete branch has its own observation identity and edge binding. One `DependencyFamily`
records the exact source occurrence, model, root attempt, completed concrete branch meanings and
branch outcomes. Successful empty closure has an empty inventory. An optional generated branch
with no model has `OPTIONAL_NO_MODEL`, rather than disappearing as successful empty. Required
classifier prerequisites remain required. Failure or cancellation prevents parent publication.

Family inventories belong to the modeled output. Family/branch/attempt identities belong to
incoming `AFFECTS` prerequisite edges, alongside `StorageScan.Binding`, rank and read state.
Execution DAG deduplication cannot erase distinct bindings: family edges are emitted per child
binding, including cached references and distinct bindings sharing one source. Observation
`HAS_CHILD` still describes native parenthood; actuator plan children describe model provenance.
No observation is retyped or moved to make it a model input.

A contextualizer receives its modeled output through the existing declared output argument
injection, then calls `scope.getDependencyFamilies(output)` and
`scope.getDependencyInputs(output, familyId)`. `getTargetObservation()` retains its existing
relationship-endpoint meaning. The family view anchors on the canonical modeled target, rejects
foreign/tampered bindings, and reads the live transaction's prerequisite edges before publication.
After publication the implementation can read matching persisted edges; an independent native
database family-inventory roundtrip is not verified by the staged-graph acceptance fixture. It validates actual source semantics and
requested mediation semantics separately; a cached source need not acquire optionality or units
from the request. Consumers must honor the returned storage binding and requested support.
This API performs no implicit unit, currency, spatial or aggregation policy.

The producer and concrete child plans use the actual Runtime scheduler. The parent runs after its
concrete dependency work. Generated optionality is preserved; the consuming model decides how
explicit absence affects its own result. This is not a weakening of required dependencies.

## Worked fixture and verification boundary

`SelectedModelClassifierSubmissionTest` enters ordinary `Runtime.submit` and actual strategy
selection, native OWL/HermiT validation, classifier planning/dispatch, coherent native snapshots,
fresh attribution and mandatory characterization lookup (NO_MODEL in this fixture), typed redeclaration, concrete model selection, scheduler,
transaction staging, graph retrieval and storage. Test adapters supply catalogue/parser transport,
component lookup and native database operations. The strategy DSL is parsed by the real parser;
the model/source ASTs and vocabulary are isolated fixtures, not production worldview additions.

The parent has one abstract `Crop HarvestCashValue of Region` dependency; it contains no authored
concrete crop list. Two observed members classify as Wheat and Maize. Independently monetary
child observations use explicit fixture valuations `3 * 5` and `2 * 11`, in common `USD@2020`;
one final graph-reading contextualizer adds 15 and 22 to obtain 37. Changing the member set to
Maize yields one concrete child and 22, although the Wheat ontology/model remains available.
Thus the observed classifications, not the ontology descendant list, drive expansion.

Prices/quantities are authored test assumptions. These results do not verify dimensional price
mediation, price discovery or FX. The necessary currency construction repair delegates the String
builder overload to its existing value overload and gives `CurrencyImpl` a deterministic definition
string. Source guards compare portable semantic snapshots, not currency object identity. No rate
or currency validation policy is introduced.

The fixture explicitly chooses zero for successful empty closure, and explicitly rejects a total
when any crop valuation is absent. Runtime expansion fabricates neither choice. Fresh/reused
classifications, Tier-0 priority, source/member mutation, failure/cancellation and separate cached
binding contracts are covered by the associated tests and evidence receipts.

The current automatic route is INIT, one deferred dependency and one abstract occurrence per
selected model, with any supported number of concrete closure branches. Pure syntax/keyed-outcome
machinery already supports multiple predicate products, but ordinary multi-occurrence planning,
shared classifier-producer/domain binding and general parent input families remain future stages.
Unsupported shapes fail explicitly. No complete recursive runtime or persistent invalidation
policy is claimed.
