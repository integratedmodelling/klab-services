## Implemented scope

- `AgentExecutions`: explicit source-parsed BEHAVIOR-only compiled registration
  against existing context, `allow_execute=True`, fixed defer/unbind flags,
  source/service/context fidelity checks and immutable registration receipt.
- `DeferredAgent`: one thread-affine attachment, no reconnect, local-only close;
  start/stop/status use the existing agent exchange and production Message wire.
- `AgentChannel`: caller-driven SelectConnection, passive exchange check, private
  bounded exclusive queue, explicit TLS/vhost/credential configuration, bounded
  confirms/I/O/cleanup, one-shot command journal, echo filtering, closed decoding,
  terminal/conflict latches and honest local-vs-remote cleanup outcomes.
- Shared fixture compares actual production-Java message serialization and
  exchange ID with Python encoding/decoding. New native-AMQP CI fixture starts
  an isolated Qpid broker with generated credentials, native Java AMQP peer,
  positive controls, negative authentication/ACL checks and independent inventory.

is false; `remote_agent_cleanup` remains UNKNOWN. Production Java control/wire

capability spoofing was used. Real broker-confirm success is currently covered
by deterministic driver tests, **not** by this Qpid live result.

## Retained failures and corrections

Evidence lives outside Git under the sibling directory
`python-agent-amqp-evidence-20261103/`; the hashes/result summary are retained in
this branch, and source tests/fixture/workflow provide the reproducible harness.

- Initial blank expected fixture intentionally failed; captured production JSON
  supplied the oracle, rather than changing Java to fit Python.
- First mock tests exposed a fake `confirm_delivery` callback signature error;
  corrected fake to the public Pika signature. Cleanup failures remain false,
  not retroactively relabeled successful because connection close later worked.
- First native attempt had an author-added duplicate test-scope dependency that
  shadowed the existing compile dependency; removed that duplicate declaration.
- Native attempts2-6 exposed Pika's unsupported confirm negotiation. Sanitized
  protocol-phase diagnostics established capability absence. This is not a
  universal claim that AMQP/Qpid implementations cannot support confirmations.
- Attempt7's **test-only** creator ACL omitted final exact-exchange auto-delete
  authority and the harness timed out. Later fixtures fix that creator ACL;
  Python still cannot create/delete the exchange. Its timeout is not a passing
  inventory/cleanup result. Later owned-process inventory found no matching
  remaining worktree processes; no restored/user service was stopped.
- Attempt8 exchanged commands but mishandled Pika's wrapped probable-vhost-denial
  exception. Added bounded, sanitized typed handling, not broad failure success.
- Attempt9 passed wire operations/negative controls but failed test cleanup by
  closing an already broker-denied Java connection. Close only if still open.
- Attempt10 passed the narrow native test. Final run additionally passes the
  existing scoped profile/authorization and native agent Java test selection,
  plus the invalid-password negative control.
- Initial broad Python invocation used undeclared all-test discovery and an
  environment missing optional fixture dependencies: seven collection errors,
  not product acceptance. Corrected to the declared CI extras and exact
  `tests/unit tests/integration` selection; retained initial failed log.
