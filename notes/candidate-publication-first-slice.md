# Candidate publication first slice

Base c8a721c2554bed3729aa5415fb006a4aec5013c5. This is an isolated, unwired infrastructure slice, not a change to live ReasonerService behavior. Hard bean-gate load/update changes belong to the discovery owner; no existing production file or shared API was changed here.

CandidatePublicationCoordinator owns a single background drain worker, one running build plus only the latest queued input, separate bean/logical phases, cooperative cancellation, source/configuration publication guard, atomic accepted-state/source/generation updates, reader leases, and exactly-once retirement/discard cleanup. Invalid beans schedule no build and logical status is NOT_RUN, not a failed OWL pass. Failed, unresolved, stale or unverified-isolation results never replace accepted state. A valid candidate publishes only when both input and expected accepted generations remain current. Guard callbacks and disposal run outside the coordinator monitor. Shutdown does not interrupt HermiT calls; returned late candidates are discarded. Weak identity tracking detects borrowed/reused state without retaining retired ontology graphs strongly. Cleanup failures are bounded and observable.

The builder must own a frozen input payload and every candidate component. isolationVerified is an explicit integration contract, not a proof manufactured by this generic class. A failed builder cleans up resources it did not return. Bundle.close must dispose only exclusively owned resources, never borrowed accepted providers/caches; even a rejected unisolated wrapper may otherwise harm accepted state during cleanup. Lease.state is borrowed: consumers must neither mutate nor close it, and must keep the lease for their entire operation. awaitIdle means worker completion, not completion of disposal for outstanding reader leases.

The publication guard is a local, nonblocking callback. Every relevant source/configuration writer must submit/invalidate before its change can make a result stale; a guard read alone does not make unrelated Resources writes transactional. The current Resources/Reasoner code has not been routed through that contract. An adapter that cannot establish these conditions must not mark isolation verified or advertise accepted publication.

Tests cover immediate bean rejection, pending accepted reads, delayed retirement, queued coalescing, stale uncooperative success, invalidation, guard mismatch/reentry/errors, unknown isolation, unresolved checks, builder failure/recovery, borrowed-state protection, cleanup failure reporting, shutdown and executor rejection. A real private OWLAPI/HermiT fixture proves that a globally consistent candidate with an impossible named class does not replace the accepted ontology. Fourteen focused tests passed in isolated compilation against the actual candidate runtime JARs; no service construction/configuration/authentication or shared dependency installation occurred.

Independent read-only review identified guard Throwable handling and cleanup-under-reentrant-lock defects in the draft. Guard invocation was moved outside the monitor with generation rechecks, failure handling unified, bean failure distinguished from logical failure, and targeted regressions added. The reviewer then reported no remaining blocker for the unwired coordinator. Existing integration semantics are not certified by these unit tests.

## Integration blockers found by independent boundary audit

- ReasonerService's final OWL field, source/domain/diagnostic registries, concept/observable/syntax/subsumption caches, matchers, emergence, authority state and strategies must belong to one semantic environment (ReasonerService.java:138,268,308,533).
- SemanticsBuilder holds concrete ReasonerService and calls reasoner.owl throughout a build (SemanticsBuilder.java:38,452). Extract a context parameter; do not temporarily swap a global field.
- OWL reaches scope.getService(Reasoner.class) inside helper callbacks (OWL.java:1287,1501,1577). Candidate scope must bind candidate-local operations, not the live accepted service.
- Lazy resolution, authority hierarchy insertion, admin definition and builder paths mutate logical state; they must be generation-routed or fail closed. Concepts compare by URN, so old/new handles require rebinding to the pinned environment.
- ObservationReasoner contains mutable strategies and concrete service callbacks (ObservationReasoner.java:20). It must be isolated too.
- Authority configuration/release invokes provider effects and shares cache/ledger paths (AuthorityBindings.java:37,244). Independent configuration IDs/storage or an explicit unsupported-isolation result are required; do not release accepted provider bindings when discarding a candidate.
- A second normal ReasonerService constructor writes configuration/runtime files, initializes components and updates global ServiceConfiguration (ReasonerService.java:649). It is not a private candidate factory.
- Existing capabilities snapshots publish metadata only, not a complete reasoning environment. Integration needs reader leases and a coherent bundle reference; an OWL-only pointer swap is unsafe.

Next coordinated implementation must add a real private compiler/environment factory and route service readers/writers through a pinned environment after the gate owner's delta is reviewed. This slice deliberately does not implement that adapter or launch the approved publication architecture. The user's publication boundary is accepted; these are engineering ownership/isolation blockers, not a request to reopen that decision.
